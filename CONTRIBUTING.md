# Contribuindo com a Comunidade K0Sec

Este guia explica como sugerir melhorias para a organização comunitária da K0Sec.

## Antes de Contribuir

Leia:

- [README.md](README.md)
- [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)
- [GOVERNANCE.md](GOVERNANCE.md)
- [ROADMAP.md](ROADMAP.md)

## O Que Pode Ser Proposto

- Melhorias em regras e documentos.
- Sugestões de eventos ou encontros.
- Ideias para integração de iniciantes.
- Propostas de organização para canais, cargos e processos.
- Checklists para atividades.
- Relatórios públicos de atividades realizadas.

## O Que Não Deve Ser Proposto

- Ataques a sistemas reais.
- Exposição de dados privados.
- Conteúdo ofensivo, ilegal ou inseguro.
- Promessas de parceria, apoio ou evento sem confirmação.
- Nomeação de pessoas para cargos sem autorização.

## Abrindo Issues

Use o template mais próximo do seu caso:

- `content-suggestion.yml`
- `event-proposal.yml`
- `community-improvement.yml`

Se a sugestão envolver segurança, privacidade ou conduta, não publique detalhes sensíveis em uma issue.

## Enviando Pull Requests

1. Crie uma branch a partir de `develop`.
2. Faça mudanças pequenas e claras.
3. Mantenha linguagem direta, acolhedora e responsável.
4. Não invente dados, nomes, contatos, eventos ou resultados.
5. Revise links e formatação Markdown.
6. Abra o Pull Request para `develop`, salvo orientação diferente da equipe.

## Estilo de Escrita

- Use português claro.
- Explique termos técnicos quando necessário.
- Evite tom corporativo exagerado.
- Evite promessas grandiosas.
- Deixe explícito quando algo é planejamento futuro.

## Commits

Use Conventional Commits:

- `docs:` para documentação.
- `chore:` para manutenção.
- `fix:` para correções.
